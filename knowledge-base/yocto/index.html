Yocto 使用知识库
yanruiheYocto
BitBake / Layer / Recipe / Image / devtool

把硬件、软件包和发行版配置组织成可复现的系统镜像。

命令是通用示例，实际构建前必须确认各层与 Yocto 发布分支相互兼容。

1. 核心概念

Yocto Project 不是一个固定发行版，而是一套用 OpenEmbedded 构建定制 Linux 系统的工具和元数据。

  • BitBake：解析元数据并执行任务。
  • Recipe（配方）：描述源码、依赖、编译、安装和打包方式。
  • Layer（层）：按功能隔离和组合配方、类、机器与发行版配置。
  • Machine：描述目标硬件平台；Image 描述最终系统镜像。
Layer → Recipe → Package → Image
  └──── Machine / Distro 配置影响解析与构建结果

2. 初始化与第一次构建

下面是通用流程，实际使用时必须让 poky、BSP 层和其他层处于相互兼容的发行版分支：

git clone https://git.yoctoproject.org/poky
cd poky
git checkout <compatible-release-branch>
source oe-init-build-env build

bitbake-layers show-layers
bitbake core-image-minimal

构建前确认 MACHINE、DISTRO、下载目录和共享状态缓存配置。第一次构建通常需要较长时间，后续构建应尽量复用 DL_DIR 和 SSTATE_DIR。

3. 创建和接入自定义层

bitbake-layers create-layer ../meta-myproduct
bitbake-layers add-layer ../meta-myproduct
bitbake-layers show-layers

建议把产品定制放在独立层中，不直接修改 poky 或 meta-openembedded。常见结构如下：

meta-myproduct/
├── conf/layer.conf
├── recipes-apps/demo/demo_1.0.bb
├── recipes-core/images/myproduct-image.bb
└── recipes-kernel/linux/linux-%.bbappend

4. 配方与镜像

配方至少要明确源码、许可证、依赖和构建任务。对现有软件的定制优先使用 .bbappend，避免复制整份上游配方：

IMAGE_INSTALL:append = " demo"

变量覆盖语法与发行版版本有关；升级分支时要检查 override 语法、层兼容性和依赖变化。

5. devtool 开发闭环

开发应用或修改已有配方时，可用 devtool 缩短“修改—构建—部署—固化”循环：

devtool add https://example.com/project.git
devtool modify <recipe>
devtool build <recipe>
devtool deploy-target <recipe> root@<target-ip>

# 源码仓库提交后固化到正式层
devtool finish <recipe> ../meta-myproduct
devtool reset <recipe>

部署到目标机前先确认 SSH、目标架构和运行时依赖；devtool finish 前确认源码仓库已经提交。

6. 调试清单

# 查看最终变量值及其来源
bitbake -e <recipe> | less

# 查看任务依赖或执行单个任务
bitbake -g <recipe>
bitbake <recipe> -c compile

# 进入配方的开发 shell
bitbake <recipe> -c devshell

# 清理配方后重新构建
bitbake <recipe> -c cleansstate

# 查询已生成包的文件归属
oe-pkgdata-util find-path /usr/bin/<program>

遇到“找不到配方”先检查层是否加入、配方名是否正确；遇到“配置没有生效”先用 bitbake -e 确认变量来源；遇到增量构建异常再有针对性地清理任务。

7. 可复现与发布

  • 固定 manifest、层分支或 commit，而不是只记录模糊版本号。
  • 记录 MACHINE、镜像目标、构建时间、构建主机和关键配置。
  • 将自定义层、配方、补丁和 conf 配置放入 Git；不要提交 tmp/、downloads/、sstate-cache/ 等生成目录。
  • 发布前完成一次干净环境构建或 CI 验证，并保存镜像校验值。
