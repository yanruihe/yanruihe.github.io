## 推荐记录格式

1. **背景**：目标、平台、版本和已知约束。
2. **操作**：可以复制执行的命令或配置片段。
3. **验证**：如何判断操作成功，给出日志、产物或测试命令。
4. **风险**：可能破坏什么、如何回滚、哪些内容依赖版本。
5. **参考**：官方文档、提交记录和关联问题。

## 知识流转

```text
采集问题 → 提炼最小复现 → 记录操作与验证 → 关联 Git 提交 → 发布到站点
```

Git 负责追踪知识和代码的演进；Yocto 负责把经过验证的配置、层和配方变成可复现的系统镜像。两者结合时，建议让每条硬件或发行版变更都对应一个清晰的提交，并记录构建分支、机器配置和镜像目标。
