Embedded Linux from scratch: Buildroot
yanruiheBuildroot
2026-09-23 · Buildroot 2025.02.18 LTS · QEMU x86_64

Build a toolchain, Linux kernel, and root filesystem from source, then boot the result in QEMU. Virtual firmware handles early boot here; a real ARM board still needs its own bootloader, device tree, drivers, and BSP.

Host · Build · Boot · Customize · Hardware

1. Prepare the host

Build on Linux as a normal user. On Windows, use a Linux VM or WSL2's Linux filesystem, not a Windows-mounted build directory. These commands target Ubuntu 24.04; consult the official host requirements elsewhere. Allow ample disk, RAM, and network capacity.

sudo apt update
sudo apt install -y build-essential git wget cpio unzip rsync file bc \
  bzip2 gzip xz-utils patch sed gawk qemu-system-x86

Use sudo only for host package installation, never for make.

2. Pin and build the image

git clone --branch 2025.02.18 --depth 1 https://gitlab.com/buildroot.org/buildroot.git buildroot
cd buildroot
git describe --tags --always
make qemu_x86_64_defconfig
make
ls -lh output/images/
test -s output/images/bzImage
test -s output/images/rootfs.ext2

The initial build fetches sources and creates the toolchain, packages, kernel, and filesystem. Do not assume a top-level make -j is needed. output/build/ holds build work, output/host/ host tools and the sysroot, and output/images/ deployable artifacts. output/target/ is not a bootable image.

3. Boot QEMU and verify

Follow the selected defconfig's board readme:

qemu-system-x86_64 -M pc \
  -kernel output/images/bzImage \
  -drive file=output/images/rootfs.ext2,if=virtio,format=raw \
  -append 'rootwait root=/dev/vda console=tty1 console=ttyS0' \
  -serial stdio -net nic,model=virtio -net user

The login prompt appears in QEMU's graphical window. In the guest, inspect:

uname -a
cat /proc/cmdline
cat /proc/1/comm
mount | grep ' on / '

Confirm the kernel, root device, init, and root mount, then shut down with poweroff. Do not hand-edit rootfs.ext2 as persistent configuration.

4. Add a boot-time action

This minimal setup uses BusyBox init, not systemd. Run mkdir -p board/demo/overlay/etc/init.d and create board/demo/overlay/etc/init.d/S99demo:

#!/bin/sh
case "$1" in
  start) echo 'Buildroot demo is ready' >/dev/console ;;
  stop) ;;
  *) exit 1 ;;
esac

Run chmod +x board/demo/overlay/etc/init.d/S99demo and make menuconfig. Set System configuration → Root filesystem overlay directories to board/demo/overlay. Save, run make, and boot again. Look for the message and run test -x /etc/init.d/S99demo in the guest. Production applications should be Buildroot packages; the overlay is a minimal demo.

5. Preserve and port

make savedefconfig BR2_DEFCONFIG=board/demo/demo_defconfig
git status --short

Commit the defconfig, overlay, patches, and version manifest, not the whole output/ directory. A real board needs a matching defconfig and validation of CPU/ABI, bootloader, kernel configuration, device tree, partitions, serial console, and flashing. A QEMU image cannot be flashed directly to an unrelated board. For build failures inspect the package and output/build/; for boot failures inspect kernel arguments, root device, and serial output. Address source and license obligations before shipping.
